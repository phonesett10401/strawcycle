# StrawCycle Film v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise the Home film to cinematic quality on laptops and in the video, with tiers that keep phones smooth (Phase A). Then add Blender-made hero objects (Phase B).

**Architecture:** A new pure module `tiers.js` picks and steps down detail tiers and parses film URL flags (tested in Node). `film.js` reads the tier for counts, pixel ratio and post-processing. Post-processing (bloom, light rays, ACES, FXAA for video) lives in a new `post.js` that is lazily imported on High and Ultra only. Phase B adds `blender/*.py` asset scripts, `models/*.glb`, and a loader in `film.js` that swaps procedural shapes for models when they arrive.

**Tech Stack:** Three.js `0.170.0` from jsdelivr. Addons are mapped as `"three/addons/": "https://cdn.jsdelivr.net/npm/three@0.170.0/examples/jsm/"` in the same import map in `index.html`. The rest is vanilla ES modules and `node --test`. Phase B uses Blender ≥ 4.2 with the `cli-anything-blender` CLI (via `cli-hub`), glTF export with Draco, and `DRACOLoader` decoders from `https://cdn.jsdelivr.net/npm/three@0.170.0/examples/jsm/libs/draco/gltf/`.

**Spec:** `docs/superpowers/specs/2026-11-19-film-v2-design.md`. It builds on `docs/superpowers/specs/2026-11-19-strawcycle-design.md`.

## Global Constraints

- Branch `feat/film-v2` in `C:\strawcycle`. No build step and no npm installs in the site.
- Three.js is pinned at `0.170.0`. Addons come from the same version's `examples/jsm/` path only.
- Under `?film=video`, `window.scFilm.render(p, t)` gives **byte-identical** frames for identical `(p, t)`. No TAA, no frame accumulation or feedback buffers, no `Math.random`, `Date.now` or `performance.now` in render paths, and MSAA stays off; FXAA handles edges there. Visitors keep MSAA on High.
- Captions and doors show before any 3D. Post-processing modules load only on High and Ultra, after the first plain frame. Extra JS for High stays under about 150 KB gzipped. Models stay under 1.5 MB in total and load after the first frame.
- Performance gate: High median frame time ≤ 16.7 ms at 1920×1080 on the RTX 5060 Laptop GPU, measured with `?film=bench` in the real browser. If it misses, reduce High counts; the budget stays.
- The existing fallbacks keep working: no WebGL, reduced motion, too slow, CDN failure, context loss, `?film=off`.
- `timeline.js` tests stay green. Story timing (`params`) is unchanged; only new visuals are added.
- Look: a warm, natural dusk. No neon, oversaturated bloom or lens-flare clichés.
- Site global constraints still apply: light and dark mode, 375 px, reduced motion, `textContent` for user text.

## Review Focus

1. **A wide-screen touch device**, such as an iPad in landscape or Safari with no `deviceMemory`, starts on Low, not High. → Task 1 `pickTier` test.
2. **A bad or missing `p`/`t` in a fixed render URL** (`?film=video&p=abc`, `p=2`, `t=-1`) clamps or defaults and never renders NaN. → Task 1 `parseFilmFlags` test.
3. **Step-down after the post-processing has loaded.** Going from High to Low disposes the composer and its render targets with no leak, and the frame stays visible (no black frame). → Task 2 manual check, `dispose` path.
4. **Post-processing addons fail to load** (CDN error partway) while the plain film already runs. The film continues on Low-style rendering, without dropping to stills. → Task 2 catch path and manual check (block `examples/jsm`).
5. **Models fail or arrive late** (404, slow network, Draco decoder blocked). The procedural shapes stay and the fibres still fold. → Task 8 manual check.

## Phase A

### Task 1: Tiers and film flags

**Files:**
- Create: `tiers.js`, `tests/tiers.test.mjs`
- Modify: `film.js` (start-up only: read the flags and tier, set the pixel ratio and counts from the tier, add the fixed-render and bench modes)

**Interfaces:**
- Produces, in `tiers.js` (pure):
  - `TIERS`: `{ low, high, ultra }`, each a frozen object `{ name, dpr, post: boolean, msaa: boolean, density: number }`. `density` is the multiplier on v1 counts: low 1, high 10, ultra 30. `dpr` is the pixel-ratio cap: low 1, high 1.5, ultra `null` (set by capture size). `post` is false on low and true on the others. `msaa` is true only on high.
  - `pickTier({ width, coarse, deviceMemory, video }) → 'low' | 'high' | 'ultra'`
    - `video` → `'ultra'`;
    - else `width < 768 || coarse || (deviceMemory != null && deviceMemory <= 4)` → `'low'`;
    - else `'high'`.
  - `STEPS = ['high', 'high-dpr1', 'low', 'stills']`
  - `nextStep(step) → string`: the next entry in `STEPS`, and `'stills'` stays `'stills'`. A low start begins at `'low'`.
  - `parseFilmFlags(search) → { mode: 'video' | 'off' | 'bench' | null, p: number | null, t: number | null, tier: 'low' | null }`
    - `p` is clamped to 0..1, `t` must be finite and ≥ 0;
    - an invalid value gives `null`, which the caller defaults to p 0, t 0;
    - `tier` is `'low'` only when `mode === 'video'` and `tier=low` is present (for capturing the phone look); otherwise `null`. `pickTier` is bypassed when it is set.

### Task 2: Post-processing pipeline

**Files:**
- Create: `post.js`
- Modify: `film.js`, `index.html` (import map gains `"three/addons/"`)

**Interfaces:**
- Consumes: Task 1 `TIERS`, tier state.
- Produces:
  - `post.js` exports `createPost(THREE, renderer, scene, camera, tier) → { render(u), resize(w, h, dpr), dispose() }`. Here `u = { sunScreen: [x, y], sun, smoke, glow }` holds per-frame values derived from `params(p, t)` only.
  - **Pipeline:**
    - `RenderPass`;
    - `UnrealBloomPass` with the threshold set so only emissive fire, embers, sun, packaging glow and city lights bloom (strength higher on ultra);
    - a light-ray `ShaderPass`: screen-space radial blur toward `sunScreen`, weighted by `sun`, with a fixed sample count (more on ultra);
    - a grade and haze `ShaderPass`: warm lift, haze increasing with `smoke`;
    - `OutputPass` with `ACESFilmicToneMapping`;
    - `FXAA` `ShaderPass` only when `tier.msaa === false && tier.post`, so on ultra.
  - The composer uses a multisampled render target only on high (`samples: 4`).
  - `film.js` imports `post.js` lazily (`await import('./post.js')`) after the first plain frame, on high and ultra only. On low it sets `renderer.toneMapping = ACESFilmicToneMapping` with no passes.

- [ ] **Step 1: Add `"three/addons/": "https://cdn.jsdelivr.net/npm/three@0.170.0/examples/jsm/"`** to the import map in `index.html`.
- [ ] **Step 2: Implement `createPost`** with the passes above. Every uniform is set from `u` each frame. Nothing reads the previous frame.
- [ ] **Step 3: Wire it into `film.js`.**
  - Lazy import after the first frame.
  - If the import fails, log once and continue with plain rendering and tone mapping (Review Focus 4).
  - Stepping down to `'low'` calls `post.dispose()` and sets `post = null` (Review Focus 3).
  - The fixed-render and video paths await the post set-up before rendering, so captures include it.
- [ ] **Step 4: Browser check.**
